# Как устроена работа (опыт «Чекпоинта»)

## Роли
- **Claude (чат)** — продукт и дизайн: план этапов, эскизы, логотип, цвета, ТЗ, архив-пакеты для агента. Проверяет отчёты агента и синхронизируется.
- **Агент Claude Code** — код на ПК пользователя в `C:\Projects\<app>`; сборка APK; git.
- **Пользователь** — решения, проверка на телефоне, запуск команд с паролями (ключ подписи), создание репозиториев.

## Цикл этапа
1. В чате: короткий план → эскизы (PNG прямо в чат) → «ок» пользователя.
2. Claude собирает **один архив** `docs/incoming/<версия>/` с `TASK.md` (шаги по порядку) + файлы (эскизы, иконки, json) и **один короткий промт**:
   «Прочитай CLAUDE.md, docs/STATUS.md и выполни docs/incoming/<версия>/TASK.md по шагам.»
3. В `TASK.md` первые шаги: разложить файлы по местам, сверка с текущим кодом (что уже сделано), дальше — работа.
4. Остановки агента (ждать ответа): сверка, эскизы (если нужны новые), проверка на телефоне, перед push и публикацией релиза.
5. Пользователь: `/clear` перед новым этапом, `/compact` — если этап длинный и не закончен.
6. После этапа пользователь приносит отчёт агента в чат → Claude синхронизируется.

## Правила ТЗ
- Только то, что нужно; новые пакеты — явно перечислить и разрешить в промте («пакет X — да»).
- Короткие пункты, точные значения (цвета, тайминги, размеры) — в json-файлах пакета, а не в тексте.
- Номер версии — следующий после фактически выпущенного (уточнять у пользователя/из отчёта: агент мог уже выпустить промежуточные версии).
- Если пользователь давал агенту задания напрямую — сначала сверка.

## Эскизы
- Claude рисует эскизы как HTML → PNG (Playwright) и показывает в чате; утверждённые кладутся в `docs/sketches/` (PNG + блоки в `sketches.html`).
- Агент дорисовывает недостающие экраны в `sketches.html`, пользователь смотрит в браузере.

## Версии (как сложилось)
Этап = минорная версия (0.1, 0.2…), правки = патч (0.7.1, 0.7.2…). Каждая сборка для людей — `versionCode` +1.
