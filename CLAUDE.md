# ShoppingList — правила для агента

Общие правила разработки пользователя действуют. Ниже правила этого проекта.

## Проект в двух словах
Мобильное приложение «ShoppingList» — список покупок с планированием по дням. Android сначала, iOS потом.
Expo (React Native) + TypeScript + expo-router + expo-sqlite. Всё офлайн, без сервера. Продукт для массового использования.
Инфраструктура перенесена из «Чекпоинта» (`C:\Projects\Checkpoint`). Продукт: `PRODUCT.md`. Эскизы и логотип: `design/`.
**Где мы сейчас — `docs/STATUS.md`** (версия, что не закоммичено, что ждёт проверки).

## Экономия токенов (обязательно)
1. Начало сессии: прочитай этот файл, `docs/STATUS.md` и задание. Больше ничего заранее.
2. Не сканируй репозиторий. Ищи точечно (Grep/Glob), читай только нужные строки (offset/limit).
3. Большие файлы — только Grep по номеру пункта или слову, не целиком: `docs/NEXT.md`, `docs/history.md`, `docs/PUBLISH.md`, `docs/IDEAS.md`, `PRODUCT.md`, всё в `design/`.
4. Никогда не читай: `node_modules/`, `package-lock.json`, `.expo/`, `assets/`, `android/`, `release/`, `*.pdf`, `docs/review-data.json`, `docs/kazakh-words-*.html`, `docs/tester-checklist-*`.
5. Проверки — с коротким выводом: `npx tsc --noEmit --pretty false`, `npx expo lint --quiet`, `npm test -- --silent`. Показывай только ошибки. Не гоняй все проверки после каждой мелкой правки — один раз в конце задачи.
6. Эскиз — только изменённый экран или блок, отдельным маленьким файлом (до ~10 КБ). Не копировать весь `screens.html` или старый эскиз.
7. Чек-листы тестировщика, PDF, формы для казахских слов, заметки релиза на 3 языках — **только по прямой просьбе пользователя**, не к каждой версии.
8. Не переписывай файл целиком ради правки — точечные правки (Edit).
9. Одна задача — одна сессия. Закончил задачу — запиши итог 3–5 строками в `docs/STATUS.md` и предложи пользователю `/clear`.
10. Простые задачи (тексты, переводы, мелкие правки, релизная рутина) — напомни пользователю, что их можно делать на Sonnet (`/model`).
11. Перед большой работой (новый экран, >5 файлов, генерация документов) — оцени объём одной строкой и спроси «делать?».

## Тесты (разумный минимум)
- Тесты — только на то, что больно сломать: миграции БД, быстрый ввод, деньги/бюджет, i18n (все ключи на 3 языках), контраст тем, резервная копия, расписание/напоминания.
- Не больше 7 тестовых файлов и ~5 проверок в файле. Без однотипных проверок «на каждый цвет / каждое слово» — один табличный тест (`it.each`) с 3–5 характерными случаями.
- Новая логика — 1–2 проверки, а не десятки. UI тестами не покрываем.

## Работа
- Делай только то, что в текущем задании. Идеи — одной строкой в «Идеи» ниже.
- Пакеты — только через `npx expo install <pkg>` и только после «да» пользователя.
- Без эмулятора. Проверка — на телефоне пользователя. `npx expo start` не запускай сам.
- ОС: Windows, PowerShell (`npx.cmd`). ОЗУ 8 ГБ.
- Эскизы утверждены: `design/screens.html`. **Любое изменение интерфейса — сначала эскиз и «ок», код только после него.** Даже мелкое и даже по просьбе тестировщика.

## Продакшен
1. `tsc`, `lint`, `test` — без ошибок.
2. Тексты — в `src/i18n/` на трёх языках (kk — на проверку носителем).
3. Миграции БД не теряют данные; уже выпущенные шаги не менять.
4. Цвета — только через `useTheme()`.
5. Нет пакетов с сетью/аналитикой; зоны нажатия ≥ 48 dp, `accessibilityLabel`.

## Постоянные требования
Сборка APK: только arm64-v8a, один APK; release с R8/minify + shrinkResources; ресурсы только ru, kk, en; keep-правила для своих нативных модулей. Подробности — `docs/RELEASE.md`.
Код: списки — FlatList/SectionList; слои экран → `src/logic/` → `src/db/` (без SQL и расчётов в экранах); тяжёлое — после первого экрана; без неиспользуемых пакетов и `console.*` в release; цвета из темы, тексты из i18n.
Проход проверки (таблица «проблема · где · что даст · риск») — перед первой сборкой и раз в 2–3 этапа; правка только одобренного.

## Сборка и релиз
- APK собирает пользователь (`powershell -ExecutionPolicy Bypass -File scripts\build-apk.ps1`); агент проверяет файл (размер, SHA-256, версия, подпись).
- Пока идёт сборка — код не править.
- После проверки файла релиз выкладывается без вопроса: `gh release create` → `latest.json` → push репозитория APK → тег и push основного. Затем `curl -sIL <apkUrl>`: 200 и тот же размер. Детали — `docs/RELEASE.md`.
- Канал уведомлений — сразу с высокой важностью.

## Код
- Код и имена — на английском, тексты — через i18n.
- Маленькие файлы: один экран или компонент — один файл.

## Ответы пользователю
До 10 строк, простым языком: что сделано и как проверить. Не пересказывай вывод команд.
