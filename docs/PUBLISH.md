## Что нужно до выпуска
- Страница магазина: название, короткое и полное описание (ru/kk/en), скриншоты, иконка 512, баннер.
- Политика конфиденциальности (приложение офлайн, данные на телефоне, сеть — только проверка обновлений; **для Play обновление из приложения через APK недопустимо — для магазина версию без самообновления**), условия, дисклеймер.
- Сборка AAB (не APK) и подпись Play App Signing; `IS_PROTOTYPE = false`; убрать пометку «Прототип».
- Закрытое тестирование: по моим данным, новым личным аккаунтам нужна группа тестировщиков на ~2 недели; проверить актуальные условия на момент выпуска.
- Казахские тексты проверить носителем (`docs/i18n-review.md`).
- RuStore как второй магазин (рынок СНГ); обновления в приложении отключить для магазинных версий.

## Отдельный GitHub-аккаунт для публикации (решение пользователя, 2026-11-07)
- Для Google Play создаётся **отдельный аккаунт GitHub** (под ник студии, не личный): там публикуются пользовательское соглашение, политика конфиденциальности и другие публичные документы, а также APK.
- Основной репозиторий с кодом может стать приватным (на личном аккаунте); публичными остаются только репозитории нового аккаунта.
- Политику конфиденциальности для Play удобно отдавать через GitHub Pages публичного репозитория нового аккаунта (стабильный публичный URL).
- **Что учесть при переезде:**
  - сейчас `UPDATE_URL` в `src/config.ts` и скрипты `make-latest.ps1` / `docs/RELEASE.md` указывают на `TimurNazmutdinov/ShoppingList-android-apk` — после создания нового аккаунта нужно перенести репозиторий APK (Settings → Transfer ownership, GitHub оставит редирект) или создать новый и обновить ссылку в приложении;
  - уже установленные прототипы читают `latest.json` по старой ссылке: сначала выпустить версию с новой ссылкой, пока старый репозиторий ещё жив, и только потом закрывать/удалять его;
  - репозиторий APK на личном аккаунте публично показывает настоящее имя — после переноса личный аккаунт в публичных ссылках не светится;
  - для магазинной версии (AAB) самообновление через APK отключается, на новый аккаунт это не влияет;
  - `gh` работает с одним активным аккаунтом: для публикации переключаться `gh auth switch` (аккаунты не смешивать).

## Ключ подписи и имя пакета при переходе на аккаунт студии (2026-11-07)
- Текущий ключ `C:\Projects\keys\shoppinglist-release.jks` создан с сертификатом `CN=Timur Nazmutdinov` — личное имя видно в сертификате APK. Для студии нужен новый ключ с нейтральными данными (CN/O = ник студии, без личного имени).
- Имя пакета `com.timurnazmutdinov.shoppinglist` тоже содержит личное имя и публично видно в адресе приложения в Google Play. Пока в Play ничего не выпущено, его ещё можно сменить (например `com.<студия>.<приложение>`); после первой публикации — навсегда.
- **Последствие:** новый ключ или новое имя пакета = Android считает это другим приложением. Обновить поверх установленных прототипов (0.6.x) нельзя: тестировщикам удалять и ставить заново, локальные списки пропадут (резервной копии в приложении пока нет — вынести «Резервную копию» (0.8) раньше или смириться с потерей данных у 2–3 тестеров).
- Поэтому «версия-мост» (новая ссылка `UPDATE_URL`) имеет смысл только пока ключ и пакет прежние: мост подписывается старым ключом. Если ключ и пакет меняются одновременно с переездом, мост не нужен: прототип остаётся на старой ссылке, новый пакет ставится отдельно.
- Рекомендуемый порядок: ник → новый GitHub-аккаунт → новый ключ + новое имя пакета + новая ссылка обновлений **одним шагом** до первой публикации в Play; старый ключ и репозиторий сохранить (понадобятся для поддержки старых прототипов). В Play включить Play App Signing (Google хранит ключ подписи приложения, у нас ключ загрузки).
- Сборка из GitHub-APK и из Play несовместимы (разные ключи подписи при одном пакете не ставятся друг поверх друга).

## Два аккаунта: как работаем (решение пользователя, 2026-11-07)
- **Личный аккаунт** (`TimurNazmutdinov`): разработка и тестирование — код (может быть приватным), текущие прототипные APK, проверка обновлений на тестировщицах.
- **Независимый аккаунт студии:** выкладываются только готовые и **адаптированные для публичности** файлы: APK/AAB, пользовательское соглашение, политика конфиденциальности, README, `latest.json` для публичной версии. Кода и личных данных там нет.
- **Идея, как это развести технически (согласовать до реализации):** два варианта сборки из одного кода через переменную окружения (`APP_VARIANT=dev|public`, `app.config.js` вместо `app.json`):
  - `dev` — как сейчас: пакет `com.timurnazmutdinov.shoppinglist`, личный ключ, обновления из репозитория на личном аккаунте, пометка «Прототип»;
  - `public` — пакет студии, ключ студии, казахское/публичное название, `IS_PROTOTYPE=false`, ссылка обновлений на аккаунт студии (или без самообновления для Play-версии).
  Оба варианта ставятся на один телефон одновременно, не мешая друг другу.
- Скрипт публикации (`scripts/publish-public.ps1`, позже): собрать public-вариант → проверить файл и SHA-256 → переключить `gh auth switch` на аккаунт студии → создать релиз и `latest.json` → вернуть личный аккаунт. Перед каждой публикацией — вопрос пользователю.
- Перед публичным выпуском проверять, что в публикуемых файлах нет личных данных (имя в сертификате, имя пакета, пути вроде `C:\Users\...`, e-mail) и нет внутренних документов (`docs/`).
